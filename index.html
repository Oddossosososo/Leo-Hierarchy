02 / Signature constructions

What makes Leo distinctive?

These are the hierarchy's defining design ideas—not claims of a proven record over every other large-number function.

C_LEO · The piggyback chain

At each relevant V_LEO step, the construction uses the ordered four-stage chain below. Each intermediate result feeds forward as fuel.

V_LEO→U_LEO→U_LEO→V_LEO

The chain is combined with the Earth-marking walk. The exact walk rules and halt condition remain open design work.

EX_LEO · Seed inheritance

EX_LEO begins from the complete chained C_LEO / U_LEO output as its Step₀ seed.

Step₀ := chained C_LEO / U_LEO output

The recursion or reflection rule that grows from this seed—and proves finite termination—has not yet been specified.

03 / Design principles

What makes this framework stronger to work with?

Its advantage is the way the project is organised and developed—not an unsupported claim that it mathematically beats every competing function.

🧱

Layered architecture

Each tier has a distinct role, so new growth mechanisms can be added without rewriting the whole hierarchy.

🔗

Fuel inheritance

The C_LEO chain explicitly passes intermediate outputs forward rather than treating each stage as an unrelated label.

🌍

Spatial computation idea

The Earth-marking walk gives C_LEO a second construction mechanism alongside function chaining.

🧭

Clear tier boundaries

The official order is recorded in one place, with each function's intended role documented separately.

🧪

Proof-aware status

Established rules, proposed mechanics, and unproven growth claims are labelled separately.

🗂️

Version history

GitHub commits can preserve earlier definitions and make every approved change traceable.

04 / Comparison convention

The RAYO rule

Project rule: RAYO(k) > k for every finite integer k. Under the Leo comparison convention, RAYO(n) only surpasses a Leo tier when that tier (or a higher tier) is passed directly into RAYO(·) as input fuel.

This convention is part of the project's specification. The inequality RAYO(k) > k by itself does not prove that RAYO(n) exceeds every Leo function at the same argument.

06 / Mathematical integrity

Big claims need exact rules.

The Leo Hierarchy is a custom googological design project. A named tier or an intended ordering is not automatically a theorem about numerical growth. To establish a rigorous comparison, each function needs a precise definition: domains, codomains, recursion, permitted theories, encodings, and termination conditions.

In particular, V_LEO's use of ZFC + I₀ and reflective fixed-point language needs a precise formal interpretation before consistency, strength, or output-size claims can be assessed. Likewise, “Conway chain” needs its exact arrow notation and evaluation convention written down.

Project standard: preserve the creator's rules exactly; mark missing definitions as open; never present an unproved comparison as established fact.
